# 课题02 · 个人手机多工况发热与掉电实测

> 选拔大纲第一阶段题库（10选2）之一。本目录为「不出门、坐桌前」即可完成的实地课题——只用你自己的手机，无需去校园找点位。

## 大纲原题（原文）
- **采样**：测试手机在待机、短视频、导航/拍摄、高帧率游戏 4 种工况下 30 分钟内每 5 分钟的电量与发热分布。
- **交付**：提交 24 组时间序列 CSV 表，分析高功耗硬件模块并提出系统省电策略。

## 你需要做的（约 2 小时，桌前完成）
1. **准备**：手机电量充到 100%（或统一一个起始值，记在备注）。准备一个记时器。
2. **四种工况各测 30 分钟，每 5 分钟记一次**（t=5,10,15,20,25,30，共 6 次/工况 → 4×6=**24 组**）：
   - **待机**：锁屏放桌上，什么都不干。
   - **短视频**：刷抖音/视频类 App（屏幕亮、扬声器出声）。
   - **导航/拍摄**：开高德/百度导航 或 连续拍照/录视频。
   - **高帧率游戏**：开一局吃性能的手游（如原神/王者高帧率）。
3. **读数**：
   - **电量%**：设置 → 电池 里看百分比（每次记下来）。
   - **电池温度℃（必填，主指标）**：用免费 App 读——`CPU-Z` / `DevCheck` / `Device Info HW` 里的「电池 / Battery 温度」项，或红外测温枪点手机背面。几乎所有手机都能稳定读到，**优先记这一列**。
   - **CPU 温度℃（选填）**：若你的 App（如 `DevCheck` 的 Thermal/Sensors 项）能稳定读到 CPU/SoC 温度，再补这一列，报告会多出一张 CPU 温升图、结论更硬（能点明"芯片是主要热源"）。读不到就留空，不影响主体分析。
4. **同框照片**（大纲硬性要求）：测的时候自拍一张「你 + 举着正在测的手机」的照，存到本目录（命名如 `selfie_verify.jpg`），作为本人实地认证。

## 填数据
- 打开 `raw_data/phone_power_template.csv`，把 24 行的 `battery_pct` / `battery_temp_c`（必填）和 `cpu_temp_c`（选填）填上（不要用示例文件冒充真实数据）。
- 填好后**另存为** `raw_data/phone_power.csv`（脚本默认读这个文件名）。

## 生成报告
```bash
cd 01-Field-Discovery/Task02-PhonePower
python3 analyze_phone_power.py            # 读 raw_data/phone_power.csv
# 或指定文件： python3 analyze_phone_power.py 你的数据.csv
```
会输出 `report.html`（电量曲线 / 温度曲线 / 掉电速率对比 / 关键发现 / 24 组原始表）。
