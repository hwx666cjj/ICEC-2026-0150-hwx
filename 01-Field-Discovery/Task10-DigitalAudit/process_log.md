# 课题10 · 过程日志（Process Log）

> 记录"日常数字任务耗时审计与 AI 批处理实证"的真实操作过程，用于选拔阶段三"真实性溯源"追问。
> 原则：**不伪造数据**——人工耗时来自用户真实计时，AI 耗时来自代码实测，样本复现用户描述的真实场景。

## 任务定义
- 重复性数字任务：**把一批命名混乱的文件夹按顺序改名为数字**（选题自大纲举例"文件重命名"）。
- 样本数：10 个。
- 人工耗时（真值）：用户将 10 个新建文件夹改名为数字，**手机计时 45 秒**。
- 原始场景复现：Windows 新建文件夹的默认命名 `新建文件夹`、`新建文件夹 (2)` … `新建文件夹 (10)`。
- 目标命名：`1` … `10`（顺序编号）。

## 操作时间线
1. **2026-11-14** 与用户对齐选题 → 选定"文件批量重命名"。
2. 用户提交真实人工耗时：**45 秒 / 10 个文件夹**。
3. 清理上一版误做（笔记提取）的伪造样本（`make_samples.py` + `raw_data/note_*.txt` 等），
   在 `raw_data/` 复现 10 个真实原始文件夹作为提交样本（含 `.gitkeep` 以便 Git 跟踪空目录）。
4. 用 AI（大模型）辅助编写 `rename.py`，Prompt 见 `AI_PROMPT.md`。
5. 运行 `rename.py --mode dry-run` 预览改名方案 → 人工确认无误。
6. 运行 `rename.py --mode execute` 在 `work/` 副本上真实改名，并实测耗时。
7. 产出 `rename_log.csv`、`time_comparison.csv`、`report.html`，提交版本。

## 关键决策与排障（体现韧性）
- **决策：原始样本只读、改名在副本**。原因：阶段三面试会要求解释数据是否被篡改；
  把"证据保护"做成脚本默认行为，比事后说明更可信。
- **决策：dry-run 预览前置**。批量改名不可逆，先让人确认 10 个映射再执行，是核心"人机校验规则"。
- **排障：公平计时**。初版容易把"复制样本到副本"也算进 AI 耗时，已修正为仅对 `os.rename` 循环计时，
  保证与人工耗时口径一致。
- **排障：空目录不被 Git 跟踪**。原始样本是空文件夹，补 `.gitkeep` 占位，确保提交后样本仍在。

## 人机校验规则（课题交付物之一）
1. **改名前预览**：dry-run 打印全部 `原名 -> 新名`，人确认后才 execute。
2. **合法性校验**：脚本自动拦截目标名重复、含 Windows 非法字符（`\ / : * ? " < > |`）。
3. **前后对照日志**：`rename_log.csv` 记录每个文件的原名/新名/状态，可回溯。
4. **人工抽检**：随机抽 2–3 个核对新名是否符合编号规则与顺序。
5. **证据保全**：`raw_data/` 原始样本不参与改名，永久保留作为溯源依据。
